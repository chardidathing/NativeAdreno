# Adreno 650 (Sony Xperia 1 II, pdx203, SM8250)

The driver was written against the Adreno 740 of the Xiaomi Pad 6S Pro (sheng, SM8550). This note records what the Adreno 650 of the Xperia 1 II needs instead, where every table came from, what the pdx203 device repository has to add around the driver, what the first boot should print, and where it is most likely to go wrong. Nothing below has run on the phone yet.

## What differs from the 740

Selected by `NativeAdrenoFamilySelect`: the a740 matches 0x43050a01 exactly, the a650 matches core 6 major 5, because the kona device tree says `qcom,chipid = <0x06050000>` where the pinned catalog lists 0x06050002 for the same silicon.

## Provenance

Everything a program writes comes from one of these, named in the generated header or the table comment next to it:

- `drivers/gpu/drm/msm/adreno/a6xx_catalog.c` at ianchb/sm8550-mainline 42f3b40c (the a650 entry 0x06050002, `a650_hwcg`, `a650_protect_regs` with `count_max` 48, `a640_gbif`, `.gmu_cgc_mode`, `.prim_fifo_threshold`, `.gmem`, `.quirks`).
- `a6xx_gpu.c` at the same commit (`hw_init`, `a6xx_set_hwcg`, `a6xx_set_cp_protect`, `a6xx_set_ubwc_config`, `a6xx_cp_init`, `a6xx_submit`, `a6xx_set_pagetable`, `A6XX_INT_MASK`, `GPU_PAS_ID`, `uche_trap_base`).
- `a6xx_gmu.c` (`a6xx_gmu_init` object sizes, `a6xx_gmu_fw_start`, `a6xx_gmu_power_config`, `a6xx_gmu_rpmh_init`, `a6xx_gmu_resume`) and `a6xx_hfi.c` (`a6xx_hfi_start`, `a650_build_bw_table`).
- `registers/adreno/a6xx.xml`, `a6xx_gmu.xml`, `adreno_common.xml`, `adreno_pm4.xml` with A6XX variant selection, and `a6xx_perfcntrs.xml` for `PERF_CP_ALWAYS_COUNT`.
- The stock kona device tree of the phone (`qcom,kgsl-3d0@3d00000`, `qcom,gpu-pwrlevels`, `gpu_opp_table`, `qcom,gmu@3d6a000`, `kgsl-smmu@3da0000`, `qcom,kgsl-hyp`, `pil_gpu_region@8681a000`, `reserved-memory@80860000`), read by `derive-a650-firmware.py`.
- Sony's kgsl (`msm-4.19/drivers/gpu/msm`) only for the GMU CX corner (`rpmh_gmu_arc_votes_init`) and as a cross check: its `a620_protected_regs`, `a650_gbif_regs`, hwcg, UBWC and chip id handling agree with the Linux tables; where it differs (fence range 0x80a008a0, IFPC on, `PC_DBG_ECO_CNTL` bit 9 `disable_tseskip`, no `RBBM_NC_MODE_CNTL` write, its own CP init list) the Linux value was kept and the difference is listed under risks.
- The firmware files themselves are pinned by size and sha256 in `a650-firmware.json`; their contents never enter git.

Reasoned rather than derived: the kernel buffer base of 16 MiB (any address above the GMEM window and below the client windows would do), the GMU corner (kgsl's value, where mainline's sm8250 tree uses a GMU OPP table this phone's tree does not have), the UBWC swizzle and macrotile bits (mainline's `qcom_ubwc_cfg_data` for sm8250, from memory, matching the sheng words), and the choice to keep Linux's values wherever kgsl differs.

## What the pdx203 device repository must add

The driver gives the device repository the same entry points sheng uses, with a family argument:

- `NativeAdrenoGmuContextBringupFamily(NativeAdrenoFamilyA650, smmu, bytes, bank, asid, slot, sid 5, progress, report)` and `NativeAdrenoGmuContextPayloads` (the debug entry comes back zero).
- `NativeAdrenoGpuContextBringupFamily(NativeAdrenoFamilyA650, ..., slot0, sid 0, slot1, sid 1, ...)` and `NativeAdrenoGpuContextBuffers` (addresses from 16 MiB).
- `NativeAdrenoAssembleGmuConfig(firmware, allocator, 0x06050000, budget, config)` selects the a650 sizes from the chip id.
- `NativeAdrenoHwInit(NativeAdrenoFamilyGet(NativeAdrenoFamilyA650), io, inputs, result)` after the GMU's OOB GPU_SET, with `inputs.ubwc` from `NativeAdrenoUbwcWordsFor` and the kgsl node's bank bit, access length and UBWC mode.
- `NativeAdrenoRing::attach(..., NativeAdrenoFamilyA650)`, `NativeAdrenoCpInit::run(..., NativeAdrenoFamilyA650)` with a zero pwrup address, `NativeAdrenoIrq::attach(io, NativeAdrenoFamilyA650)`.
- `AdrenoA650BuildStartup` with the `gfx.lvl`, `mx.lvl` and `cx.lvl` aux bytes of the AOP command database at 0x80860000 (size 0x20000; the sheng parser `ShengGmuCommandDbInputs` reads the same format but insists on the BCM and `gmxc.lvl` records the a650 does not need, so the device repository wants a variant that stops at the three rails), `AdrenoA650PerfVote` for the first GX_BW_PERF_VOTE (bandwidth index 0).
- `AdrenoZapPlanImage(native_adreno_zap_image, size, 0x2000, &plan)` then the SIP calls as sheng's `zapAndSecure`: init_image with `plan.metadata_bytes` (header then hash) in a 4 KiB aligned coherent buffer, mem_setup over 0x8681a000 for `plan.load_bytes` (the segment is relocatable), the segment copy at `paddr - load_base`, auth_and_reset, then `CP_SET_SECURE_MODE` 0 through the ring.

The register offsets of the gpucc and gcc branches (the equivalents of sheng's `GPB_CC_*` and `GPB_GCC_*`) are not in any pinned input of this work: the device repository has to pin `gpucc-sm8250.c` and `gcc-sm8250.c` and derive them the way `prepare-sheng-gmu.py` does. The gdsc addresses above come from the device tree and agree with mainline's `gpu_cc_cx_gdsc` (0x106c) and `gpu_cc_gx_gdsc` (0x100c) offsets within the block, which is a useful cross check once those files are pinned.

The power sequence kgsl runs before the GMU (`kgsl_gmu.c` `gmu_enable_gdsc`/`gmu_enable_clks`): `gpu_cx_gdsc` on (poll the hw ctrl word), then `gpu_cc_ahb`, `gmu_clk` at 200 MHz, `cxo_clk`, `axi_clk`, `memnoc_clk`; the SMMU clocks before the SMMU is touched. GX is never enabled by the kernel: the GMU brings it up after the OOB GPU_SET, and `GMU_SPTPRAC_PWR_CLK_STATUS` bits 6 and 7 (a6xx positions, `NATIVE_ADRENO_A650_GMU_GX_OFF_BITS`) report it.

The GMU cold start sequence the device repository writes (its `ShengGmu.c`) follows `a6xx_gmu_fw_start` for the a650 family, with these changes against the sheng one: FAL veto writes to `GPU_GMU_CX_GMU_CX_FALNEXT_INTF` and `GPU_GMU_CX_GMU_CX_FAL_INTF` (A6XX offsets 0x1f8f1 and 0x1f8f0), TCM retention through `GMU_GENERAL_7` and no CX misc window, the RSC setup of `NativeAdrenoA650RscSequence` at `RSCC_SEQ_MEM_0_DRV0` with hidden TCS data 0x80000000 and the PDC enable only, the chip id into `GMU_HFI_SFR_ADDR` and the log into `GPU_GMU_CX_GMU_PWR_COL_CP_MSG`, `GMU_AHB_FENCE_RANGE_0` 0x802800a0, the GBIF QSB writes of `NativeAdrenoA650GbifCx`, the a6xx power config (inter frame control 0x9c40400, RPMh control bits 0xf11), the log write pointer reset through `GPU_GMU_CX_GMU_PWR_COL_CP_RESP` in `a6xx_gmu_start`, 16 firmware records, and the five objects without the debug one. Everything else (SYSRESET, BOOT_CONFIG 2, HFI table, CM3_CFG 0x4052, the FW_INIT_RESULT mask chosen by the DTCM version word, HFI_CTRL_INIT) is unchanged.

Kernel arguments the pdx203 board should mirror from sheng's (`sheng-gpu-power`, `sheng-gpu-perf`, `sheng-gpu-zap`, `sheng-gpu-pool`, `sheng-gpu-metal`, `sheng-fb-gpu`) under its own prefix; `sheng-gpu-perf` maps to `AdrenoA650PerfVote` (1 = 290 MHz, 3 = 480 MHz, bandwidth index always 0). The kit build (`build-native-adreno-kits.py`) adds `AdrenoA650.c` and `AdrenoZap.c` to the kit sources and replaces the firmware block with `python3 kits/AdrenoFirmware/AdrenoFirmwareEmbed.py --pins kits/AdrenoFirmware/a650-firmware.json --firmware-dir .cache/firmware/pdx203-gpu --output build/native-adreno/firmware.S`, after a `--check` of the local files.

The accelerator ABI device info for the Metal plugin: chip id 0x06050000, `gmem_bytes` 0x120000, `gmem_base` 0x100000, `uche_trap_base` 0x1fffffffff000, bank bit 16, swizzle 6, macrotile 1, UBWC 4. Turnip takes the a650 path from the chip id (no concurrent binning, no LPAC, `a6xx` IR3).

## Expected first-boot observations

In the order the device repository's probe rows should show them:

1. Family: `NativeAdrenoFamilySelect(0x06050000)` returns the a650 info (gmem 0x120000, kernel base 0x1000000). A null here means the chip id in the ADT is not what the kona tree says.
2. SMMU: ID0/ID1/ID2 of the gpu SMMU read with CX on and `gpu_cc_hlos1_vote_gpu_smmu_clk`'s equivalent running; the global space is sized by IDR1 as on sheng. The kona window is 0x10000, not sheng's 0x40000.
3. GMU context: step 7 (Ready), `routes_verified` 1, `ttbr0` with ASID 1 and the table pool's physical address, `spans` 4 (no debug object).
4. Firmware: the embedded GMU image validated at 41548 bytes, `AdrenoFirmwarePlanGmu` reporting 16 records (7 with payload).
5. Cold start: SYSRESET 1, TCM retention `GMU_GENERAL_7` 1 after the write, RSC idle, HFI status 0 before; after the load, `CM3_FW_INIT_RESULT` matching 0xbabeface or 0x100 (the DTCM word at +0xff8 decides, as `a6xx_gmu_start`), then `HFI_CTRL_STATUS` bit 0.
6. HFI: five commands acknowledged (ids 4, 3, 14, 10 plus 11 for IFPC when enabled), no F2H error. A firmware error on the bandwidth table (id 3) is the first place a wrong cmd-db address would show.
7. GX: after the GX_BW_PERF_VOTE (level 1, bandwidth 0) and the OOB GPU_SET (set bit 30, ack bit 31, non-legacy), `GMU_SPTPRAC_PWR_CLK_STATUS` with bits 6 and 7 clear, `RBBM_STATUS` readable.
8. hw_init: `NativeAdrenoHwInitResult` step Done, `clock_cntl_before` 0 and `hwcg_programmed` 1 on a cold GPU.
9. CP: `CP_ME_INIT` fence observed, then the scratch `CP_MEM_WRITE` fence and value, as sheng's C10 row.
10. Zap: init_image, mem_setup, auth_and_reset returning 0, then the `CP_SET_SECURE_MODE` 0 fence.

## Risks, most likely first

1. The GMU corner and fence range come from kgsl and Linux respectively, and the two disagree (kgsl 0x80a008a0 for the fence, mainline's sm8250 GMU OPP level for the corner). A GMU that does not reach FW_INIT_RESULT, or AHB fence errors in `GMU_AO_HOST_INTERRUPT_STATUS`, point here first; both values are single defines (`NATIVE_ADRENO_A650_GMU_FENCE_RANGE`, `--gmu-level`).
2. The stock `a650_sqe.fw` reports version 0x093 in its first payload dword; mainline's `a6xx_ucode_check_version` refuses anything below 0x095 for the a650 ("other security fixes"). The vendor kgsl runs it without that check, and this port does not enforce it either. A newer `a650_sqe.fw` from linux-firmware is the fix if the CP misbehaves on init, and a security consideration regardless.
3. The kernel buffers at 16 MiB assume the a6xx GMEM window defaults to 1 MiB with the range registers untouched. If the CP faults on its first ring fetch at 0x1100000, move `kernel_iova_base` (one field in `NativeAdrenoFamily.cpp`).
4. The zap carveout `pil_gpu_mem` is `no-map` and may already be assigned to TrustZone by the stock ABL; `mem_setup` failing or the segment copy faulting leaves the CP in secure mode, as the sheng probe handles with `sheng-gpu-zap=0`. `RBBM_SECVID_TRUST_CNTL` is never written: a650 devices ship a zap shader.
5. The GMU SMMU and GPU SMMU share one `qsmmu-v500` instance with TBUs; kona's `qcom,actlr` entries and the 0x10000 window differ from sheng. If the context bank programming reads back wrong, compare `NativeAdrenoGmuContextReport::mismatch` first.
6. UBWC: `RBBM_NC_MODE_CNTL` = 1 and the level 2 swizzle follow mainline's sm8250 config from memory, not a pinned file. Wrong values show as garbled compressed surfaces rather than a hang; pin `drivers/soc/qcom/ubwc_config.c` and regenerate.
7. IFPC is off (Linux). kgsl runs the a650 with IFPC on; turning it on later only needs `enable_ifpc` 1 in `AdrenoA650VoteInputs` and the hysteresis config the device repository's GMU sequence writes (`NATIVE_ADRENO_A650_GMU_INTER_FRAME_CTRL`, `NATIVE_ADRENO_A650_GMU_PWR_COL_HYST`, `NATIVE_ADRENO_A650_GMU_IFPC_CTRL_BITS`).
8. The gpucc and gcc branch offsets are unpinned here; a wrong clock enable is the one failure that can hang the bus before any row is drawn, which is why sheng's staged, read-only modes 1 to 3 should be copied as they are.
9. kgsl sets `PC_DBG_ECO_CNTL` bit 9 (`disable_tseskip`) on the a650 and mainline does not; mainline runs the a650 without it, so it stays off.

## Tests

`tests/run-host.py` builds the hostsim tests with a plain clang (cross compiled and run under qemu-user when `CC`, `CXX`, `LDFLAGS_EXTRA` and `RUN` say so). The a740 expectations are untouched and the a650 cases sit beside them: `test_family`, `test_hwinit` (both programs write for write), `test_gpuctx` (buffer placement), and the a650 blocks of `test_cpinit`, `test_irq`, `test_ring`, `test_gmumem` and `test_gmuconfig`. AdrenoFirmware's `test-host.py` runs the kit tests with the pinned Linux oracles plus `test_a650`, `test_zap` and `test_gmu_a650`. The kernel compile check of the whole tree with sheng's defconfig runs on the `a650-check` branch of chardidathing/UniXNU through the macOS build workflow.
